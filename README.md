# Mock-сервер для СП 2 MCA АБС ЦФТ

<h4 align="center">
  <a href="https://github.com/plp-lang/as2mca-mock/blob/main/LICENSE">
    <img src="https://img.shields.io/badge/license-MIT-blue.svg" alt="MIT License" />
  </a>
</h4>

Неофициальный, свободный **Mock-сервер** для сервера приложений Платформы 2 MCA АБС ЦФТ. Программа проксирует запросы к реальному серверу приложений, **кэширует** все ответы на диск и в автономном режиме воспроизводит их без доступа к банковскому контуру. Это позволяет разрабатывать и тестировать инструменты, интеграции и клиентские библиотеки вне защищённой сети банка.

Проект создан исключительно в некоммерческих, образовательных и исследовательских целях. Основные сценарии использования:

- **Разработка и отладка клиентских библиотек** (например, [as2mca-api-ts](https://github.com/plp-lang/as2mca-api-ts) или [as2mca-api-rs](https://github.com/plp-lang/as2mca-api-rs)) без постоянного доступа к рабочему контуру АБС;
- **Автоматизированное тестирование** в CI/CD пайплайнах – фиксация эталонных ответов и повторяемые тесты без внешних зависимостей;
- **Демонстрация и обучение** – показ работы с API на стабильном наборе данных без риска повлиять на рабочие схемы;
- **Изолированная разработка** интеграционных шлюзов и микросервисов, взаимодействующих с АБС.

> [!WARNING]
> Данный проект является **неофициальным** и **не аффилирован** с компанией «ЦФТ» или разработчиками Платформы 2 MCA.
> Библиотека создана на основе самостоятельного анализа поведения клиента «ЦФТ - Навигатор» и открытых сетевых обменов.
>
> Проект не гарантирует _полную_ совместимость с сервером приложений. В зависимости от:
>
> - Версии протокола обмена,
> - Конфигурации сервера, установленных патчей и обновлений ТЯ,
> - Политик безопасности и сетевых настроек конкретного контура.
>
> Структура запросов/ответов API и жизненный цикл сессий могут отличаться.
>
> Использование этого проекта в продуктовых контурах банков или в нарушение лицензионных соглашений и политик безопасности «ЦФТ» осуществляется исключительно на ваш страх и риск.
> Автор не несет ответственности за любые прямые или косвенные последствия использования этой библиотеки.

## Совместимость

Библиотека тестировалась с следующими версиями:

- **Protocol** (`protocolInfoGet`): `9.54`;
- **ТЯ**: `7.6.5.0`, `7.7.4.9`;
- **АБС**: `26.2.03-26.2.14`;
- **СП DBI Oracle**: `3.11.115-3.11.128`;
- **СП DBI Oracle в режиме эмуляции Платформы 1**: `2.67.9`;
- **Java-компилятор**: `7.9.6-7.9.16`.

Если ваш сервер использует другие версии, некоторые структуры могут не совпадать.
В таком случае прошу открыть Issue или Pull Request.

## Пример использования

### 1. Запуск сервера в режиме записи (cache+proxy)

Загружаем официальный образ:

```sh
docker pull ghcr.io/plp-lang/as2mca-mock:latest
```

Запускаем контейнер в режиме `cache+proxy`.
В этом режиме сервер проксирует запросы к серверу приложений и одновременно сохраняет все ответы в локальный кэш:

```sh
docker run --rm --name as2mca-mock -p 3000:3000 \
    -u root \
    -v $(pwd)/.cache:/data \
    -e AS2MCA_MOCK_MODE="cache+proxy" \
    -e AS2MCA_MOCK_WEB_APP_NAME="NIGHT" \
    -e AS2MCA_MOCK_URL="http://127.0.0.1:7000/TEST/" \
    -e AS2MCA_MOCK_USERNAME="IBS" \
    -e AS2MCA_MOCK_PASSWORD="password" \
    ghcr.io/plp-lang/as2mca-mock:latest
```

> Примечание: Убедитесь, что локальная директория `./.cache` доступна для чтения и записи пользователю внутри контейнера.

### 2. Настройка и запуск тестов клиента

Кнонируем тестируемый проект, например [as2mca-api-ts](https://github.com/plp-lang/as2mca-api-ts):

```sh
git clone https://github.com/plp-lang/as2mca-api-ts
cd as2mca-api-ts
bun install
```

Создайте файл `.env` (или экспортируйте переменные) и укажите адрес запущенного **mock-сервера**:

```sh
AS2MCA_API_USERNAME="IBS"
AS2MCA_API_PASSWORD="password"
AS2MCA_API_URL="http://localhost:3000/NIGHT/"
```

Запустите тесты:

```sh
bun test
```

Если тесты прошли успешно — вы всё сделали правильно! В директории `./.cache` должен появиться файл `cache.db`.

### 3. Переход в автономный режим (`cache`)

Остановите текущий контейнер и запустите его заново в режиме чтения из кэша (`cache`).
Теперь сервер не будет делать внешние сетевые запросы, а будет отвечать строго на основе ранее записанных данных:

```sh
docker stop as2mca-mock
docker run -d --name as2mca-mock -p 3000:3000 \
    -u root \
    -v $(pwd)/.cache:/data \
    -e AS2MCA_MOCK_MODE="cache" \
    -e AS2MCA_MOCK_WEB_APP_NAME="NIGHT" \
    ghcr.io/plp-lang/as2mca-mock:latest
```

Снова запускаем тесты:

```sh
bun test
```

Если тесты прошли успешно, значит сервер успешно воспроизвел сохраненные ответы.
Файл `./.cache/cache.db` можно транспортировать для локальной разработки,
коммитить в репозиторий (через Git LFS), использовать в CI/CD пайплайнах.

## Переменные окружения

| Переменная                              | Описание                                       | Обязательная                 | По умолчанию            |
| --------------------------------------- | ---------------------------------------------- | ---------------------------- | ----------------------- |
| `AS2MCA_MOCK_MODE`                      | Режим работы (`cache`, `proxy`, `cache+proxy`) | Нет                          | `cache+proxy`           |
| `AS2MCA_MOCK_URL`                       | Адрес сервера приложений 2 MCA                 | Да (только в режиме `proxy`) |                         |
| `AS2MCA_MOCK_USERNAME`                  | Имя пользователя для Basic-аутентификации      | Да (только в режиме `proxy`) |                         |
| `AS2MCA_MOCK_PASSWORD`                  | Пароль для Basic-аутентификации                | Да (только в режиме `proxy`) |                         |
| `AS2MCA_MOCK_CACHE_PATH`                | Путь хранения данных                           | Да (только в режиме `cache`) |                         |
| `AS2MCA_MOCK_WEB_APP_NAME`              | Имя веб-приложения                             | Нет                          | `platform2mca`          |
| `AS2MCA_MOCK_HOST`                      | Хост сервера                                   | Нет                          | `0.0.0.0`               |
| `AS2MCA_MOCK_PORT`                      | Порт сервера                                   | Нет                          | `3000`                  |
| `AS2MCA_MOCK_LOG_FORMAT`                | Формат логирования                             | Нет                          | `compact`               |
| `AS2MCA_MOCK_LOG_FILTER` или `RUST_LOG` | Уровень логирования                            | Нет                          | `info`                  |
| `AS2MCA_MOCK_CORS_ALLOWED_ORIGINS`      | Список разрешенных url для CORS (через `,`)    | Нет                          | `http://localhost:8000` |

## Разработчику

Требования:

- Docker для сборки и запуска образа;
- Rust 1.95+ и Cargo для локальной сборки.

Локальная сборка образа:

```sh
docker build -t as2mca-mock:dev .
# или со своей версией Rust
docker build --build-arg RUST_VERSION="1.95" -t as2mca-mock:dev .
```

Запуск локально собранного образа:

```sh
docker run --rm -p 3000:3000 \
    -u root \
    -v $(pwd)/.cache:/data \
    -e AS2MCA_MOCK_MODE="cache" \
    -e AS2MCA_MOCK_WEB_APP_NAME="NIGHT" \
    ghcr.io/plp-lang/as2mca-mock:latest
```

Сборка без Docker

```
cargo build --release
./target/release/as2mca-mock
```
